# Gimli 2.0 → HTMX: сводный план полного переноса

Начат 2026-09-03, сверен с реализацией 2026-09-04, обновлён под контейнерный
рантайм и живую инфру 2026-09-08.

**Что изменилось с момента сверки.** Рантайм ушёл с Cloudflare Workers на один
Docker-образ в k3s (4 сентября) — всё, что ниже говорило «Worker», переписано.
Инфру подняли 7 сентября: dev-хост `gimli.promova.com`, секреты в Vault
(`gimli_dev`, `gimli_prod`), заполнение — `funnel-engine-vault-env.md`.
Аналитика доведена до паритета с продом 8 сентября — матрица расхождений и
осознанных отклонений в `gimli2-analytics-parity.md`.

Решение принято: Gimli 2.0 целиком переезжает на server-rendered HTMX-движок
(`~/myProject/funnel-engine`, Hono в контейнере на k3s). Цель: новую воронку
можно вайбкодить с нуля как данные, без React, по всему пути
**онбординг-квиз → email → sales page (с down-sale) → upsell → downsell-for-upsell → thank-you**,
включая вход существующего юзера и юридический контент из Strapi.

Этот документ — оглавление и статус. Детали в спеках ниже, каждая с `file:line`
в монорепе. Спеки описывают ПРОД и остаются справочником; что из них уже
перенесено, смотри в §2 и §4.

## 1. Где движок сейчас (факт на 2026-09-04)

Репозиторий: `github.com/Promova/gimli`, приватный, ветка `main`. 14 коммитов
поверх initial commit Вадима Труфина. `pnpm typecheck`, `pnpm validate`,
`pnpm test` и `pnpm test:e2e` проходят, CI гоняет все четыре сам.

**Механизм закрыт.** DSL квиза и пейволла, условный слой, тема, шестнадцать
типов секций, цепочка после оплаты, авторинг.

| | |
|---|---|
| роуты | `/kilo`, `/sierra`, `/golf`, `/delta`, `/alpha` — имена прода |
| типы секций пейволла | 16 (прод композит из 16) |
| условная копия | `$byAnswer`, `$rules`, `variants` по трём осям |
| тема | 24 токена в CSS custom properties в первом байте |
| цепочка | апселл, даунселл, thank-you, кука `fe_pp` с зашифрованным order_id |
| авторинг | `pnpm scaffold`, скилл `/new-funnel`, `pnpm validate` |
| тесты | 148 кейсов в шести наборах + 54 e2e |

**Замеры.** Входной экран квиза против прода: FCP 5 444 → 692 мс, 155 → 24
запроса, 883 → 293 KB. Пейволл: наша часть 47 248 байт в трёх запросах, SDK
Solidgate 191 084 байт. Сравнения пейволла с продом нет — `/sierra` отдаёт 503.

**Чего нет:** публикации конфигов без деплоя, preview на ветку, приёмки
вайбкодингом. (Раздел писался под Workers и говорил «KV-публикация» — механизм
отпал вместе с рантаймом, задача осталась, см. §4a.)

## 3. P0-риски: как они разрешились

1. **Существующий email — было названо «вечным лоадером», это оказалось
   неверно.** `getLocalAnswers` при отсутствии ключа возвращает `{}`, а не
   null, и набор ответов не пуст из-за синтетического ответа про уровень, так
   что сохранение проходит и страница едет дальше. Реальный дефект хуже, потому
   что незаметен: платформа сохраняла ПУСТОЙ результат под вошедшим юзером, а
   настоящие ответы оставались на анонимном uid. Закрыто в `6bcf0c1`.
2. **Silent one-click под FTC.** Закрыто в движке: подписка под FTC всегда идёт
   через форму, что бы ни объявлял конфиг. Но FTC-флаги по-прежнему false для
   всех стран, то есть гейт не проверен на живых флагах. Остаётся к GrowthBook.
3. **`order_id` как чардж-токен без auth.** Закрыто: зашифрован через
   `sealIdentity`, в HttpOnly куке на два часа, открывается только под вызов.
   Идемпотентность эндпоинта так и не подтверждена — остаётся к бэкенду.
4. **`/sierra/{slug}/{userId}` из URL.** Движок сегмент с userId не принимает
   вовсе. Баг прода остаётся, к security.
5. **Hand-off до email невозможен.** Не начато, ждёт security sign-off.

## 4. Фазы: что вышло

| фаза | статус | коммит |
|---|---|---|
| 0 гигиена | сделано | `3fc6e39`, `3a36b15`, `04197ca`, `4b08d7d` |
| 1a условный слой | сделано | `0938978` |
| 1b тема | сделано | `776ba91` |
| 1c экраны и секции | сделано | `1bc5a7f` |
| 1d commerce | сделано, но иначе, чем планировалось | `47ce3a8` |
| 2 existing user | частично: P0 и детекция сессии | `6bcf0c1`, `a574f64` |
| 3 post-purchase | сделано | `9dd9459` |
| 4 authoring | сделано | `09bbae7` |
| 5 паритет и пилот | частично: замер пейволла | `a574f64` |

**1d разошёлся с планом по решению Алекса.** Никакого биндинга на Strapi
pricing-rule: автор называет три productId, движок идёт с ними в
`/v1/billing/products`, а поиск правильных айди уезжает в авторинг через
Walhalla MCP. Проверено: три айди живой воронки настоящие, а dev-каталог
отдаёт по ним пустоту, отсюда фолбэк. Поведение при нерешённой цене —
не 404 и не авторские цены, а отсутствие карточек и CTA.

**Что нашлось по ходу и не планировалось.** Пять дефектов, каждый закрыт:

1. `X-Pixel-Mirror` на экране лоадера 17.9 KB, блок заголовков 19.5 KB, выше
   лимита Cloudflare в 16 KB. Молчаливая потеря всей браузерной аналитики на
   самом дорогом экране. Миррор переехал в тело фрагмента.
2. Существующий email: платформа сохраняла пустой результат квиза под вошедшим
   юзером, реальные ответы оставались на анонимном uid. Движок теперь отдаёт
   набор ответов в формате платформы перед hand-off.
3. `user_type` всегда `unregistered`, при том что прод отдаёт `registered` для
   вошедшего визитёра. Расхождение в поле, по которому сегментируют.
4. `skipText` был в схеме и в двух живых экранах, а рендерер его не читал:
   экраны обещали пропуск, которого нет.
5. `green` и `pink` были валидными значениями `surface` без единого CSS-правила:
   секция могла попросить фон и молча не получить его.

Плюс две правки собственного валидатора: корень считался от текущего каталога,
и проверка полей варианта сравнивалась с инстансом вместо схемы.

## 4a. Что осталось

**Приёмка вайбкодингом.** Механизм собран, но ни одной воронки через него не
сделано. Нужен бриф. Это то, ради чего всё остальное и делалось.

**Остаток фазы 2.** Hand-off через custom token — ждёт security sign-off на ключ
сервис-аккаунта. Подписывать его теперь будет процесс в контейнере, а ключ
приедет из Vault через ESO, но сам вопрос не изменился: это ключ сервис-аккаунта
в рантайме, который отдаёт HTML. Ветка копирайта по `providers` — можно делать,
не начата.

**Остаток фазы 5.** Сравнение пейволла с продом (`/sierra` в 503), чеклисты
паритета (30 пунктов money-path, 25 post-purchase, 18 email). Свой
`funnel_name` — решено 8 сентября: пилот пишется под тем же именем, отдельное
имя заводим к моменту замера, иначе события движка и прода в Amplitude
неразличимы. Route split закрыт (см. §5).

**Публикация конфигов без деплоя.** Раньше значилось «KV-публикация» — KV
принадлежал Workers и с переездом отпал. Сути это не меняет: конфиги, воронки и
каталоги вбандлены в `dist/` и парсятся один раз за процесс, поэтому правка
копирайта по-прежнему требует сборки. Не начато намеренно — любой внешний
источник конфига обойдёт `pnpm validate`, единственное, что стоит между
сгенерированной воронкой и живой. Нужен дизайн с валидацией при публикации и
отказом при чтении.

**Preview на ветку.** `wrangler versions upload` больше не при чём. В
контейнерной модели это либо ветка-неймспейс в k3s с собственным хостом, либо
короткоживущий деплой на тот же dev-хост. В CI есть проверки, деплоя нет —
вопрос к Богдану, вместе с логами (см. §5).

## 5. Что ждёт людей

**Решено Алексом по ходу:** префиксы роутов (имена прода), поведение при
нерешённой цене (не рендерить карточки), отказ от pricing-rule, прямой пуш в
main, шрифты self-hosted woff2.

**GrowthBook / комплаенс — самое неприятное, и сузилось до одного.**
`us_pricing_now_then` и `ftc_soft_changes` резолвятся false для всех стран. Пока
это так, движок молча не покажет US-раскрытия, а это регуляторный риск, а не
косметика.

Две гипотезы отпали 8 сентября. Первая — что подставлялся не тот SDK-ключ: с
серверным ключом приходит 389 фич, то есть подключение работает, а оба флага
всё равно false. Вторая — про формат `country` (ISO против полного имени):
движок отправляет ISO, GrowthBook отвечает, флаги false. Остаётся targeting
rules — нужен тот, у кого есть к ним доступ. Заодно `anti-fraud-protection`
умеет молча поставить `sandbox: true` и вернуть 200.

**DevOps — route split закрыт, появились два новых пункта.** `/kilo/*` живой
роут прода, а Cloudflare не умеет wildcard в середине пути, значит движок и
платформа не могли оба обслуживать `/kilo` на одном хосте. Решено своим хостом:
`gimli.promova.com`, поднят 7 сентября. Одинаковое имя роутов остаётся
правильным для полной миграции; для пилота вопрос «кто владеет путём» больше не
стоит.

Гео на зоне проверено и работает — в зеркале пикселей приходит `country: "UA"`,
значит `cf-ipcountry` доезжает и EEA-гейт согласия не выключен по недосмотру.

Открыто: (1) логов движка нет ни в одном k3s-датасорсе Loki, а без них серверную
аналитику отлаживать нечем — движок пишет каждое событие в stdout ДО внешнего
гейта, и Amplitude отвечает 200 с `events_ingested: 0` на неверный ключ, так что
«не отправили» и «отправили, но отвергли» без лога неразличимы; (2) CDN-правило
на `/img/*` и `/vendor/*` — раньше их отдавал edge, теперь процесс.

**Security.** Подпись custom token в контейнере (ключ сервис-аккаунта из Vault
через ESO). Non-httpOnly кука `stsTokenManager`, на которую опирается детекция.
И баг прода `/sierra/{userId}`, берущий юзера из URL, а не из сессии.

**Бэкенд.** Идемпотентность `POST /v3/billing/upsales` и TTL `order_id` как
чардж-токена. Rate-limit `check_email_provider` по IP пода (раньше значилось «по
IP Worker-ов» — адрес другой, вопрос тот же: весь трафик воронки приходит с
небольшого набора адресов). Живо ли `/sign-in?custom_token` или `/autologin`.

**Продукт и контент.** Бриф на первую воронку. Нужен ли `/delta` в MVP (у 3 из 5
живых модулей его нет). Согласится ли дизайн на токены и закрытый набор секций —
главный вопрос, потому что «свобода дизайна» это причина существования Gimli 2.
Канонический ROSCA-текст, их в монорепе пять. (`funnel_name` пилота — решено,
см. §4a.)

**Аналитика — паритет доведён, одно решение осталось не моим.** 8 сентября
закрыты двенадцать расхождений, включая расхождение суммы покупки в 100 раз и
полностью отсутствовавшую браузерную половину Purchase; детали и осознанные
отклонения в `gimli2-analytics-parity.md`.

Не тронуто: событие лоадера отправляет в браузер всю расшифровку квиза, а оттуда
в dataLayer и в любой настроенный тег. Это и вес, и приватность. Транспорт я
починил, содержимое payload — нет, это решение не моё. Рядом встал такой же
вопрос: серверный TikTok квиза шлёт `properties: envelope`, то есть весь конверт
воронки с ответами, тогда как прод шлёт только хешированный email.

## 6. Что не делать

- Не строить `score`, `has()`, jumps, loop-back — прод не использует.
- Не портировать `/xray`, `/confirmation-banner`, fluent switch, AI-Tutor, spin wheel, `useSendStripeAnalytics`, двойной фаер close-событий.
- Не ходить в Strapi напрямую из движка — прокси через `/api/legal/*` платформы.
- Не «улаживать» коды ошибок, regex email, порядок `revenue_started_checkout` — это форма метрики.
- Не строить A/B внутрь движка сейчас: прод сплитует клонированием воронки, `ab_arm` всегда undefined. Отдельное решение.
